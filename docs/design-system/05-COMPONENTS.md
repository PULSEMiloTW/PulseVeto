# 元件規範

尺寸為新專案預設。所有元件使用共用色彩與間距 Token，沿用平台原生語意與既有元件能力。

## 按鈕與操作

| 類型 | 外觀 | 使用方式 |
| --- | --- | --- |
| 主要 | 實色品牌底、明確前景 | 同一操作群組通常一個主要動作 |
| 次要 | 表面底與邊框 | 返回、取消或輔助操作 |
| 文字／圖示 | 低視覺重量 | 重複列表操作，需有可存取名稱 |
| 危險 | 危險語意色 | 刪除等破壞性動作，明確寫出對象 |

建議高度至少 44px、左右內距 16px、圓角 8–12px，圖示 18–20px。按鈕文字用「儲存設定」「建立專案」等動詞＋對象。

| 狀態 | 行為與可見結果 |
| --- | --- |
| Hover | 邊框或底色輕微變化，不改變排列 |
| Focus | 清楚外框，保留鍵盤焦點 |
| Active | 小幅底色變化，避免位移影響點擊 |
| Disabled | 保留辨識度，必要時說明不能操作的原因 |
| Loading | 保持寬度、顯示「儲存中…」、防止重複提交 |

導頁使用連結，觸發行為使用按鈕。複製後顯示「已複製」；複製失敗提供錯誤回饋。PulseVeto 存取卡的複製主動作維持 2:1 配置，次要圖示綁定實際隊名；其他專案按操作優先順序決定。

## 表單

- 必須有持續可見且關聯至欄位的標籤，不以 placeholder 代替。
- 輸入高度 44–52px、字級 16px、圓角 8–12px；多行輸入按內容增高。
- 說明置於欄位附近，錯誤同時顯示文字與狀態，透過 `aria-describedby` 建立關係。
- 失敗後保留已填內容；提交失敗時將焦點移至錯誤摘要或第一個錯誤欄位，避免每次輸入都搶焦點。
- 必填標示一致，選用合適的 `type`、`autocomplete` 與 `inputmode`。
- 敏感原文放第二層顯示對話框；可見介面不預先暴露權杖或密鑰。

## 卡片、列表與資料表

- 卡片用 16px 圓角、16–24px 內距、1px 邊框，陰影只在需要區分層級時使用。
- 同類資料優先列表，以對齊、留白、分隔線建立秩序；不要每欄再包一張卡。
- 卡片主連結與內部按鈕不可形成巢狀互動元素。
- 表格有明確欄名，文字靠左、數值靠右；排序控制提供目前排序狀態。
- 空列表提供原因與可執行下一步；空值顯示「尚未提供」等明確文字，不假造數字。

## 導覽與全域控制

目前位置同時使用文字／圖示與背景識別。可展開群組有清楚控制與 `aria-expanded`；不要依顏色猜測目前頁面。

語言與明暗主題整合在頁首或一致的全域控制區。沿用 PulseVeto 時使用既有「文A」語言圖示；新產品若變更，應全站一致。手機導覽支援關閉、Escape、導頁後關閉，並處理焦點與背景捲動。

## 對話框與回饋

- 對話框含明確標題、關閉方式、初始焦點、Tab 焦點範圍與關閉後焦點恢復。
- 說明「刪除哪個對象」及後果；不可逆動作依風險採明確確認，不對每個可回復動作加確認。
- 一般訊息可用 `role="status"`；需立即處理的錯誤可用 `role="alert"`，避免每次更新都打斷讀屏。
- 載入、空白、失敗、成功、唯讀與權限不足都有對應畫面。視覺禁用不等於伺服器授權控制。
