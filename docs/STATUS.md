# 狀態頁

公開入口為 `/status`，唯讀 API 為 `/status/api?days=7`（支援 7、30、90）。Pulse 全域管理側欄的「狀態頁管理」開啟 `/admin/status`；管理 API `/api/manage/status` 只允許有效全域管理員，寫入沿用 CSRF、Origin 與 audit，版本衝突回傳 409。賽事單位無法管理。

主站啟動後每 60 秒探測 localhost 的首頁、文件、狀態頁、管理/HQ 入口、地圖與登入 API、Socket.IO polling 握手，以及 SQLite 查詢。管理/HQ 入口只確認未登入者收到登入導向，不代表已驗證授權後功能。Socket.IO 只驗證連線握手，不代表對局房間、推播或重新連線完整正常。

隊伍 BP、賽事管理、公開結果、Overlay 及其 API 以實際 HTTP 請求觀測，沒有流量時顯示未知，不使用真實 token 製造監測。4xx（含未授權、過期、並行衝突、輸入拒絕）另列拒絕次數，不納入被動可用率。5xx 列為失敗；超過 1,500 ms 列為效能下降。URL、query、token、IP、請求／回應內容均不保存，只保存固定元件代號、分鐘時間與統計。

紀錄使用既有 SQLite `SystemSetting`，鍵為 `status.day.YYYY-MM-DD`，保留最近 90 天（UTC）。可用率是有紀錄檢查中的成功比例；時間覆蓋率是有檢查的分鐘數／期間分鐘數。新安裝、停止監測、程序停機和遺失紀錄都不能當作正常或推造歷史。最後紀錄超過 150 秒時顯示未知；獨立外部監測仍是偵測網站完全離線、DNS、TLS、Cloudflare 與外網可達性的必要工具。本機狀態頁在主站停機時也無法提供服務。

管理員可以暫停／恢復監測，新增、修改、解決或移除事件／排程維護，選擇受影響元件、嚴重程度及開始／結束時間。公告標題與說明是公開文字；請勿填入秘密。公告不改寫觀測紀錄或可用率，維護時段仍計入原始檢查。選擇深淺色與 zh-TW、zh-CN、en-US、ja-JP 沿用站內偏好；管理員自行輸入的公告保留原文。

部署需更新主站程式與 public 檔案並按正式流程啟動服務。沒有 schema 變更或正式 migration；開發測試不代表正式監測已啟用。
